# Linux 服务器路径与运行配置

路径依据 [服务器数据与路径归档](服务器数据与路径归档.md)（2026-10-30）。

## 默认目录

| 用途 | Linux 默认路径 / 行为 | 覆盖入口 |
|---|---|---|
| 数据集 | 优先项目 `data/shapenetvipc` 软链接，否则 `/home4/zt26/data/raw/shapenet_vipc/ShapeNetViPC-Dataset` | `VIPC_DATA`，优先级最高 |
| 官方权重目录 | `/home4/zt26/data/raw/shapenet_vipc/checkpoint`（归档时为空） | `EGIINET_WEIGHTS_DIR` |

| 单个训练/测试权重 | 默认不加载，从零训练 | `EGIINET_WEIGHTS` |
| 训练清单 | 项目 `data_pick_list/train_plane_10000_list.txt` | `EGIINET_TRAIN_LIST` |
| 验证/测试清单 | 项目 `data_pick_list/test_list.txt` | `EGIINET_TEST_LIST` |

`runtime_paths.py` 集中管理目录；环境变量中的相对路径以项目根目录解析，并展开环境变量和 `~`。Windows 默认使用项目内的 `datasets/ShapeNetViPC-Dataset`、`checkpoints` 和 `runs`，便于本地检查。分析脚本显式传入的 CLI 路径仍以当前工作目录解析。

## 是否每次都要 export

**使用上表的默认目录时，不需要 export 数据和输出路径。** Python 会自动定位项目根目录，直接运行 `main.py` 也不需要设置 `EGIINET_ROOT` 或 `PYTHONPATH`。

只有覆盖默认配置时才需要传环境变量。`export` 在当前终端及其启动的子进程中一直有效，同一终端多次训练无需重复设置；新开终端或重新登录后通常需要重新设置。写入 `~/.bashrc` 的设置会在加载该文件的新 Bash 会话中生效。一次命令前的 `变量=值 python ...` 只影响该次运行。

## 按顺序执行：使用当前配置从零训练

下面命令在服务器 Bash 终端中按顺序执行，假定代码已放在归档约定的目录、环境及 CUDA 扩展已安装。GPU 示例使用 0 号卡，请先检查占用，再将最后一行的 `0` 改成实际空闲卡编号。若通过 SSH 运行，需保持会话连接；长时间训练可先进入 tmux 会话再执行这些命令。

```bash
# 1. 初始化 conda，并激活迁移后的项目环境。
source /home4/zt26/miniconda3/etc/profile.d/conda.sh
conda activate py3.9_egiinet

# 2. 进入代码目录。
cd /home4/zt26/code/egllnet

# 3. 查看 GPU 占用情况。
nvidia-smi

# 4. 清除之前的路径覆盖和权重设置，使用本文默认路径，从零训练。
unset VIPC_DATA EGIINET_OUTPUT EGIINET_TRAIN_LIST EGIINET_TEST_LIST EGIINET_WEIGHTS

# 5. 启动训练。只对本次运行指定 GPU 和数据加载进程数。
CUDA_VISIBLE_DEVICES=0 EGIINET_NUM_WORKERS=2 python -u main.py
```

按当前 `config_vipc.py`，这会使用 plane 的 10000 条训练清单、2048 点输入、batch size 2，训练 100 个 epoch。每次训练创建 `/home4/zt26/runs/<时间戳>_egiinet_plane_2048/`，实际目录在日志的 `Experiment directory` 中显示。点数、网络结构、损失权重、类别和训练轮数仍通过 `config_vipc.py` 修改。

同一终端中，训练结束后再次执行第 5 步即可开始新实验，无需重新激活环境或 export 路径。新开终端后可重新按第 1–5 步执行。

### 自定义路径或改用完整训练清单

先执行上面第 1–4 步，再用下面命令替换第 5 步。示例路径与归档一致，需要搬迁数据或输出时修改相应值；完整训练清单依然受 `cfg.TRAIN.CATE` 类别过滤控制。

```bash
VIPC_DATA="/home4/zt26/data/raw/shapenet_vipc/ShapeNetViPC-Dataset" \
EGIINET_OUTPUT="/home4/zt26/runs" \
EGIINET_TRAIN_LIST="/home4/zt26/code/egllnet/data_pick_list/train_list.txt" \
CUDA_VISIBLE_DEVICES=0 EGIINET_NUM_WORKERS=2 \
python -u main.py
```

这些变量仅作用于这次命令；下一次直接运行第 5 步，会重新使用默认清单与默认路径。

## 独立测试与加载权重训练

独立测试必须指定已存在的检查点；加载模型和优化器继续训练还需要检查点包含 `optimizer`。恢复逻辑沿用原实现，不恢复 epoch 和完整调度器状态。

```bash
export EGIINET_WEIGHTS="/home4/zt26/runs/<实验目录>/checkpoints/ckpt-best.pth"
python -u main.py --test
```

## 实验目录

一次训练创建一个目录，点数和类别写入名称：

```text
/home4/zt26/runs/YYYYMMDD_HHMMSS_微秒_egiinet_plane_2048/
├── checkpoints/        # ckpt-best.pth、ckpt-epoch-NNN.pth
├── logs/               # train/、test/ TensorBoard 日志
└── configs/
    ├── config_vipc.py
    ├── resolved_config.json  # 含环境变量覆盖后的实际配置
    └── git_revision.txt      # 启动时 HEAD；无 git 时记录 unavailable
```

Git 版本只记录提交号；尚未提交的源码差异需自行提交留档。日志中打印实际实验路径。旧 `output/<点数>/<类别>/checkpoints/<时间>/` 下的权重仍可通过 `EGIINET_WEIGHTS` 或推理脚本 `--weights` 使用。

```bash
tensorboard --logdir /home4/zt26/runs --port 6006
export EGIINET_WEIGHTS_DIR=/home4/zt26/data/raw/shapenet_vipc/checkpoint
PYTHONPATH=. python show_analyze/run_official_inference.py --category plane --count 12 \
  --output ./result/inference
```

官方权重按 `<category>-ckpt-best.pth` 命名；预留目录为空时需先放入权重。分析/绘图入口和结果文件命名保持原有约定。

## 数据读取

- 初始化仅检查三个数据子目录与索引，不递归扫描数百万个文件。
- 清单按 `utf-8-sig` 读取，兼容 UTF-8 BOM、LF/CRLF、空行、末行无换行及反斜杠分隔符；每行必须是 `类别ID/物体ID/视角ID`，视角范围 00–23。非法行报告文件名及行号，类别过滤后无样本会报错。
- 点云 `.dat` 保持原来的二进制 pickle 格式，以 `latin1` 兼容 Python 2 NumPy pickle；没有把 `.dat` 当文本或其他二进制格式读取。读取后转换为 float32，并检查非空、有限的 `[N,3]` 数据。
- 图像转 RGB；元数据按 `utf-8-sig` 读取。使用目录拼接定位文件，避免分隔符、点号目录及换行影响路径。
- 保留随机图像视角、坐标旋转、归一化与 partial 重复补点行为；训练/测试继续执行原 FPS。

## 环境与验证

环境和 CUDA 编译方式见 [WSL 历史安装记录](REPRODUCE_WSL2.md)；当前服务器环境以归档为准。保留已有 `CUDA_VISIBLE_DEVICES`，也可用 `EGIINET_DEVICE` 指定；`EGIINET_SEED` 默认 1，`EGIINET_NUM_WORKERS` 默认 2，支持 0。

数据读取回归测试使用临时构造的 pickle 点云、PNG 和相机元数据，覆盖路径含中文/点号、清单换行、对齐/随机视角及无效输入。真实服务器数据、CUDA 扩展和完整训练需在服务器验证。Windows 本地验证遇到 OpenMP 重复加载，测试进程临时设置了 `KMP_DUPLICATE_LIB_OK=TRUE`；项目运行代码未加入该设置。
